# 评审分离与校准合同 v1

## 1. 原则

生成、评测开发、金标建设、资格运行、内容评审、事实评审、盲判和最终审计必须可追溯分离。每个评审记录必须声明评审者类型、身份、所用模型或人工资质、可见材料、校准版本、开始时间和输出摘要。

“独立”指没有参与当前受评对象的生成或修改，没有读取被禁止的答案或其他评审者在制结论，并由运行清单证明角色不碰撞。不能仅靠不同显示名称证明独立。

## 2. 角色

| 角色 | 主要职责 | 不得兼任 |
|---|---|---|
| 数据保全者 | 源字节、摘要、六格访问与复制事件 | 当前案例生成者 |
| 金标建设者 A/B | 独立建立参考断言、主张原子或评测标签 | 同一案例裁决者、评测开发者读取密封答案 |
| 金标裁决者 | 只裁决分歧并记录依据 | 任一原标签作者、当前生成者 |
| 评测开发者 | 调整抽取、原子化、蕴含、召回器和阈值 | G3 密封答案评审者 |
| 生成器开发者/作者 | 开发或产生候选 | 当前候选的内容、事实或最终审核者 |
| 内容评审者 | 价值、产品指纹、套路六轴 | 当前候选作者 |
| 事实与授权评审者 | 事实、授权、披露和隐性误导 | 当前候选作者 |
| 盲判评审者 | 隐去产品答案后的产品识别 | 读取映射答案后再作盲判 |
| 最终审计者 | 从原始记录独立复算 | 当前实现开发者、当前内容主审 |

## 3. 金标与 M0

1. 每个 M0 资格对象必须由两名独立建设者先标；分歧由第三角色裁决。
2. G2 开发金标与 G3 密封资格金标不得共享案例答案。
3. 评测开发者可读取 G2，不得读取 G3 答案；生成器开发者不得读取 G3。
4. 已泄漏的 G3 案例可以降级为开发回归，但不能继续计入资格证据。
5. 金标不是“多数模型投票”。每个标签必须绑定源证据区间、判定规则和裁决理由。

## 4. 套路轴的交叉分派

R5 的不相交产品分块不能用于估计套路轴评审尺度。新分派必须让相同候选对被两名评审者独立判断，并使每位评审者覆盖多个产品家族、正类、负类和产品必要语法例外。

最低要求：

- 资格集中至少 300 个全新双审候选对；
- 正类、负类均至少 100 对，必要语法例外至少 20 对；
- 同一对的两份首判在互不可见条件下完成；
- 两份首判和裁决结果全部保留；
- 报告总体、正类、负类一致率，分家族一致率、裁决率、类别分布与 95% 置信区间；
- 类别分布使一致性系数不可解释时如实记录，不得伪造为 0 或 1。

## 5. 第一门正式评审覆盖

- 机器形状和确定性检查覆盖全部材料和案例；
- 内容主审覆盖资格与稳定性批次全部正向首次输出，包括最终拒绝项；
- 事实与授权主审覆盖全部正向首次输出；
- 第二专家遵守 V1.1 的不少于 48 条且每产品至少 2 条；
- 全部高风险、意见不一致、一票否决分歧和省略式误导发现必须复核；
- 守护审查只复核结构、硬门与高风险样本，不重复冒充另一套全量内容主审。

## 6. 一致性指标

必须同时报告：

1. 原始一致率；
2. 正类一致率和负类一致率；
3. 批准/不批准一致率；
4. 硬否决意见一致率；
5. 加权一致性系数或预先声明的替代系数；
6. 分歧裁决率；
7. 各评审者的正类率、负类率和弃权率；
8. 分产品家族和风险等级的最差值。

一致性系数不是唯一真相。高原始一致但类别极不平衡、低正类一致或高裁决率都不得宣称量规已稳定。

## 7. 封包与防泄漏

评审包只能包含完成任务所需的最小材料。产品编号、中文产品名、路线答案、生成器版本提示、分配单内部标签和其他评审结论默认隐藏。映射文件与内容包分开冻结，并在发包前做标签泄漏扫描和双射检查。

## 8. 当前状态

本合同只定义未来分派和校准要求。当前没有新评审分派、资格金标或一致性报告，不得据此把 M0 标为通过。
