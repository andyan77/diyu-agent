# 密封材料保全协议 v1（SEALED_CUSTODY_PROTOCOL）

> 真源：v2.4 §三 3.7 + v2.5 §三 3.7′ + P1 §十八。M1 只用合成标记测试，不接触真实密封材料。

## 1. 密封对象

QUAL-A、QUAL-B、隐藏 40（题面、双盲标注、金标、冻结结果）；未来任何被里程碑合同声明为密封的载荷。

## 2. 保全铁律

1. **明文不进作者可读 Git 历史**：主仓只存数量、摘要、密文或保全回执；工作树共享 Git 历史，不是保密边界；
2. **保全角色**只见数量/摘要/回执；技术性物理隔离（独立目录/工作树/文件系统边界），禁提示词软约束（E11 前科×2）；
3. **凡接触明文的任何会话**（制作、保全、审查、运行）：全新非 fork 会话 + `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` + 会话结束登记（会话标识、可见材料清单、销毁/留存方式）；
4. 泄漏给禁止角色 → 受影响集合整组失效，只能降级为开发回归并重建全新密封集（STOP_DATA_LEAKAGE）。

## 3. 密封摘要 denylist

- 每个密封载荷冻结时登记其 sha256 至 `state/SEALED_PAYLOAD_DENYLIST.v1.json`（M1 仅合成标记）；
- **撞库扫描**（`tools/sealed_scan.py`）在产品仓候选、交付物、任何导出树上执行；命中 = 停（v2.5 §七 新增停线 ③）。

## 4. 扫描范围（最低集，P1 §十八）

Git 当前树；Git 全历史与 pack 对象（`git rev-list --objects --all` + `cat-file`）；LFS 指针与对象；子模块；软链接目标；压缩包成员（zip/tar 递归一层以上按需）；缓存目录；日志；提示词文件；构建产物；自动记忆目录快照。

## 5. M1 边界

本协议在 M1 只落文本 + 合成标记负向测试（`tests/test_sealed_custody.py`）；真实密封载荷的登记与扫描自 M3 起随保全角色启用。
