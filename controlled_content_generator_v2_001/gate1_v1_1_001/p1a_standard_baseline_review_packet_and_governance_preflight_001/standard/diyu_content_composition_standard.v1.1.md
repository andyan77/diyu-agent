## 1. v1.1相对v1.0的核心修订

1. 项目已改为单一主仓。删除旧编排仓、旧检索仓和旧知识仓之间的强制接力，不再把旧仓库别名写成当前运行时所有者。
2. 第一版不强制使用RAG（检索增强生成）。通用内容资产可以按结构化字段确定性选择；将来确有规模或开放检索需要时，检索结果只是内容编排计划的一类可选输入。
3. 将评价拆为四个分阶段生效门：
   - 第一门：生成器与300条基线；
   - 第二门：内容编排计划；
   - 第三门：成品内容候选；
   - 第四门：自动检查与完整回归。
4. 当前第一门不得要求正式内容编排计划、企业运行数据库、Dify（低代码智能体编排平台）工作流或真实租户运行已经建成，消除循环前置。
5. 300条唯一口径改为240条正向父级内容知识加60条缺料、冲突、授权不足或不适用路线案例，不再采用“300条正常样本再加60条异常样本”。
6. 冻结120条只是参考语料。只有完成20产品映射、来源追溯、去重和人审的条目才能计入240条正向基线。
7. 八类内容编排资产保留为长期逻辑能力视图，但不建设八套数据库，也不要求当前阶段八类各15条。
8. 通用资产、合成测试案例、企业事实和运行输出分别适用不同字段与硬门；通用资产不得为了满足格式而伪造租户、品牌或真人授权。
9. 机器硬门和人类语义、领域、合规判断分开。机器检查全部材料，内容主审审核密封批次全部正向首次输出，第二专家复审不少于20%，守护审查方不重复承担全量内容主审。
10. 等级、处置动作、生命周期状态和原因码分开记录；不再用一个字段同时表达质量、路由和批准状态。

## 2. 标准目的

本标准用于判断笛语内容生成与编排体系是否能够持续生产：

> 事实边界清楚、内容产品可辨、角色自然、服装行业具体、表达多样、现场可执行、来源可追溯并可长期积累的内容候选与内容组件候选。

本标准同时防止以下假完成：

- 把冻结参考语料直接冒充正式运行资产；
- 把组件数量冒充父级内容数量；
- 把表达原型冒充品牌、商品、员工、顾客或事件事实；
- 把20个内容产品压成同一种开头、冲突、反转和升华模板；
- 生成器自己批准自己的输出；
- 用尚未建设的内容编排计划或运行系统阻断当前生成器验收；
- 用“全部阻止”制造安全检查全绿；
- 为满足文档而建设八套数据库、20套生成系统或层层嵌套的治理门。

本标准暂不评价服装领域本体和旧知识工程是否完整，也不把旧知识资产、旧检索链或旧仓库收口设为第一门前置。

## 3. 核心原则

1. **一个项目、一个主仓、一个正式内容资产模型、一个正式内容编排计划。**
2. **生成与批准分离。**生成器只产生候选，独立人审或批准流程决定是否进入批准分区。
3. **事实与表达分离。**通用表达资产回答“怎样表达”，企业真实输入回答“真实发生了什么”。
4. **先硬门，后评分。**虚构、越权、泄露、跨租户、非法状态升级等问题不得用高文采分抵消。
5. **按对象适用。**不是所有对象都需要租户、真人授权、内容编排计划或最终输出字段。
6. **同一案例逐阶段附加证据。**后续阶段优先复用同一300条案例并附加计划、输出和回归结果，不重复生产多套300条。
7. **先小批验证，再按缺口扩量。**数量由覆盖缺口和一次通过率决定，不按固定比例机械扩产。
8. **不过度治理。**每项检查必须对应真实风险、失败模式或下游消费需求；纯报告不能代替可运行能力。

## 4. 评价对象与对象边界

| 对象 | 中文定义 | 当前第一门是否评价 | 不得冒充 |
|---|---|---:|---|
| 父级内容知识候选 | 一条可映射到内容产品、可派生组件并保留完整来源的内容母体 | 是 | 面向用户的已发布内容 |
| 内容组件候选 | 从父级内容或新生成候选中拆出的可复用表达组件 | 是 | 企业事实、完整范文或正式服务资产 |
| 路线案例 | 用于验证缺料、冲突、授权不足和不适用处理的测试案例 | 是 | 正向内容资产或真实企业事件 |
| 内容编排计划 | 将内容产品、组件、企业输入、事实槽和输出限制形成的一次生成计划 | 否，第二门生效 | 第一门的组件包或测试组合 |
| 成品内容候选 | 根据正式内容编排计划生成、等待人审的用户可读或可拍内容 | 否，第三门生效 | 已批准、已发布或生产就绪内容 |
| 自动检查与回归系统 | 验证格式、版本、血缘、重复、状态、兼容和关键安全不变量 | 分步评价 | 内容领域专家或人类语义判断 |

### 4.1 三类数据必须分开

| 数据类 | 示例 | 是否可直接当作真实企业事实 |
|---|---|---:|
| 通用内容与表达资产 | 场景动作、角色视角、叙事方式、视听语法、反套路规则 | 否 |
| 企业真实输入 | 门店日记、员工口述、商品和库存、顾客回访、图片、视频、授权记录 | 是，但必须有来源、适用范围和授权 |
| 运行产物 | 内容编排计划、生成输入包、成品候选、人审记录 | 取决于其绑定的真实输入，不得自行补造 |

### 4.2 目标数据流

```text
经人审的通用内容资产
          +
企业本次真实输入
          ↓
唯一内容编排计划
          ↓
Dify表单与工作流
          ↓
成品内容候选
          ↓
人工审核、修改、导出
```

第一门只验证这条链未来需要的生成器、父级内容、组件和路线案例，不宣称整条运行链已经落盘。

## 5. 四个分阶段验收门

### 5.1 第一门：生成器与300条基线（当前生效）

目的：证明生成器能够面向20个内容产品产生可追溯、可区分、可拆解、可人审的候选，并对缺料和高风险输入作出正确动作。

必须具备：

- 20个内容产品定义和各自最低输入、必需组件、禁配与缺料规则；
- 冻结120条的只读产品映射与合格计数；
- 父级内容、派生组件和路线案例的独立对象合同；
- 来源、父级、证据区间、生成器版本和规则版本；
- 240条正向父级内容知识和60条路线案例；
- 全量机器检查、全量主审、第二专家复审和不可变冻结清单。

本门明确不要求：

- 正式内容资产数据库已经物化；
- 正式内容编排计划已经建成；
- 企业真实输入数据库已经建成；
- Dify工作流已经接通；
- 真实品牌、员工、顾客或门店材料已经取得；
- RAG（检索增强生成）已经接入；
- 云端部署、生产流量或自动发布已经开启。

允许使用明确标记的通用或合成测试案例验证事实槽、授权规则和缺料动作。合成测试内容不得进入面向用户的正式内容分区。

### 5.2 第二门：内容编排计划（未来生效）

启用前提：正式内容资产数据库和企业真实输入数据库均已成立。

评价内容：

- 内容产品选择；
- 内容组件选择与兼容；
- 企业事实、来源、授权和时间边界绑定；
- 必填事实槽、素材槽和角色槽；
- 缺料、冲突、过期、撤回和不适用处理；
- 输出格式、平台、时长、角色、风格和禁止事项；
- 版本、输入摘要和组件引用可追溯。

内容组件测试包、临时候选组合或第一门的生成任务说明不得冒充正式内容编排计划。

### 5.3 第三门：成品内容候选（未来生效）

启用前提：第二门通过，Dify表单和工作流已接通。

评价内容：

- 对内容编排计划的忠实执行；
- 事实、人物、商品、事件和主张没有越界；
- 20产品用户价值、结构和体验可辨；
- 角色、平台、时长、视听和一线执行可行；
- 人审、修改、回查和导出记录完整；
- 不自动发布。

### 5.4 第四门：自动检查与完整回归（分步建设，最终收口）

自动检查从第一门开始逐步建设，最终验证：

- 当前格式和所有已支持旧版本；
- 新增可选字段和合法文件不会被旧检查误阻；
- 未知主版本隔离并关闭失败；
- 检查器不会通过“全部阻止”获得假安全；
- 快速必需检查和完整回归分层运行，不层层重复调用；
- 同一输入和固定版本重复检查结果一致；
- 隐藏验收集不会被生成器调参污染。

## 6. 300条第一门基线

### 6.1 唯一数量口径

| 分区 | 每个内容产品 | 20个产品合计 | 用途 |
|---|---:|---:|---|
| 正向父级内容知识 | 至少12条 | 240条 | 验证产品差异、内容质量、组件派生和表达多样性 |
| 缺料、冲突、授权不足或不适用路线案例 | 至少3条 | 60条 | 验证阻止、请求补料和安全降级动作 |
| 总评价基线 | 15条 | 300条 | 第一门验收集 |

60条路线案例必须独立编目，不得混入可用于生成的正式内容资产分区。

### 6.2 冻结120条的计数规则

冻结只表示正文和摘要不得被静默修改，不表示自动满足20产品基线。

每条只有同时通过以下检查才可计入正向240条：

1. 映射到一个主要内容产品；
2. 来源和父级关系清楚；
3. 与其他条目不存在仅换词或近重复；
4. 通过本标准适用于第一门的人审；
5. 不被解释成真实企业事实或运行时正式内容；
6. 具有可拆解、可复用或可用于生成器校准的真实价值。

设冻结120条中最终合格数为 `N`：

```text
新增正向数量 = 240 - N
新增路线案例 = 60
新增案例总量 = 300 - N
```

组件派生数量不得用于替代父级内容数量。

### 6.3 批次与探针规则

1. 先冻结评价标准、产品分配、生成器版本和案例分区，再运行资格探针。
2. 建议资格探针为40条，默认每个产品1条正向加1条路线案例；若采用其他分配，必须在运行前声明理由和覆盖关系。
3. 探针后若修改生成器核心逻辑、主要提示、选择规则或硬门，原探针只能作为开发证据，必须使用新的隐藏案例重跑资格探针。
4. 探针后若核心版本未变，且评价标准和案例未被定向调参，探针可计入300条。
5. 后续批次大小根据 `N`、各产品缺口、人审承载量和一次通过率计算，不预先机械固定为70条。
6. 两个稳定性批次应使用同一冻结生成器核心版本；第一批暴露核心问题时，第二批停止，先定向修复并重新取得资格。
7. 原始候选、失败候选、重试和修复记录必须保留，不能只保留通过结果。

### 6.4 密封批次与最终基线必须分开

生成器质量不能只看最后挑出的好材料。每个资格或稳定性批次必须在生成前锁定输入清单、产品分配、生成器版本、规则版本和随机配置，形成“密封批次”。首次输出失败后不得删除并用替补样本重算分母。

```text
首次可接受率
= 首次输出即达到甲级或乙级且无硬门失败的正向候选数
÷ 密封批次全部正向首次输出数

最终批准率
= 经最多一次轻微修订后获得批准的正向候选数
÷ 密封批次全部正向首次输出数
```

要求：

- 密封批次首次可接受率总体不低于90%；
- 每个产品达到12条验证样本时，至少11/12首次可接受；
- 所有密封批次中的编造事实、越权授权、跨租户、近原文复制和自行批准均为0；
- 最终300条基线中的240条正向材料必须全部获得批准；
- 未获批准的候选保留在批次失败记录中，不计入最终240条，但仍计入生成器通过率分母。

## 7. 通用评价顺序

```text
对象识别与适用性判断
→ 机器硬门
→ 人类语义与合规否决门
→ 对象专属评分
→ 缺陷分级
→ 等级和处置动作
→ 第二专家复审或裁决
→ 状态变更
→ 运行清单与摘要冻结
```

硬门失败的对象不进入普通100分评分，直接隔离或拒绝；失败原因必须保留。

## 8. 机器硬门

### 8.1 硬门一：对象、格式与版本

所有对象必须具有：

- 唯一标识；
- 对象类型；
- 格式版本；
- 生成器版本或产生工具版本；
- 规则版本；
- 生命周期状态；
- 产生时间；
- 所属批次。

父级内容和组件还必须具有父级或来源标识。未知主版本必须返回“不支持的格式版本”并隔离，不得自动通过。

租户标识只在企业事实、企业运行计划和成品内容中强制；通用内容资产应明确标记为通用范围，不得伪造租户。

### 8.2 硬门二：来源与血缘

不同对象适用不同追溯链：

| 对象 | 最低追溯链 |
|---|---|
| 冻结参考语料 | 冻结清单、正文摘要、来源记录、批准记录 |
| 父级内容候选 | 输入来源、生成器版本、规则版本、产品归属、父级标识 |
| 内容组件候选 | 父级标识、父级摘要、证据区间、转换规则、组件版本 |
| 路线案例 | 测试来源、预期动作、标准原因码、案例版本 |
| 内容编排计划 | 企业输入、资产引用、事实槽、授权记录、规则版本 |
| 成品内容候选 | 内容编排计划、生成输入摘要、生成器版本、输出摘要 |

当前对象不存在的未来链路必须标为“不适用”，不能伪造内容编排计划或企业事实引用。

### 8.3 硬门三：事实与表达分离

每项材料必须声明真实模式：

| 真实模式 | 含义 | 可否当作企业事实 |
|---|---|---:|
| 来源支撑事实 | 有可核验来源和适用边界 | 在边界内可以 |
| 通用表达 | 表达方法、结构、角色观察方式或内容原型 | 不可以 |
| 合成测试 | 为验证路由和安全而构造的测试材料 | 不可以 |
| 企业输入事实 | 由当前企业提交并带权限、时间和对象范围 | 在授权范围内可以 |
| 未知或待补充 | 事实尚未取得 | 不可以 |

禁止把假设性商品、顾客、员工、门店、时间线、效果、文学化场景或测试材料写成真实发生。

### 8.4 硬门四：事实、主张与证据

凡含事实性陈述或可验证主张，必须能够回答：

- 来自哪个来源；
- 适用于哪个对象、时间、地点、产品、版本或批次；
- 是观察、经验、检测结果、供应商资料还是正式承诺；
- 允许使用多强的确定性语言；
- 有哪些适用边界和反例。

通用表达组件不包含事实性主张时，本门可以标为不适用，但不得因此获得额外分数。

### 8.5 硬门五：内容产品输入合同

每个内容产品必须定义：

- 必填事实槽；
- 必填素材槽；
- 必填角色槽；
- 必填授权；
- 可选输入；
- 必需组件；
- 可选组件；
- 禁止组合；
- 缺失处理。

缺少输入时只允许：

| 机器动作 | 中文含义 | 使用条件 |
|---|---|---|
| `BLOCK` | 阻止 | 高风险、明显不适用或无法安全降级 |
| `REQUEST_INPUT` | 请求补充 | 缺少可以由用户补齐的事实、授权或素材 |
| `DEGRADE` | 安全降级 | 可以转为提纲、采集任务、补拍清单或非事实输出 |
| `ALLOW` | 允许 | 所有强制条件均满足 |

不得通过模糊措辞掩盖强制输入缺失。

### 8.6 硬门六：授权、隐私与租户隔离

本门按对象适用：

- 通用资产不得包含可识别真实个人或企业秘密；
- 合成测试案例不得借用真实顾客、员工或品牌身份；
- 企业运行材料必须检查人物、肖像、声音、评价、素材、期限、撤回和使用范围；
- 企业事实、商品、库存、门店、人员和内容不得跨租户混入；
- 无企业或租户语境的通用资产不强制填写虚假的租户字段。

### 8.7 硬门七：内容编排计划忠实度

本门从第二门开始生效，第一门标记为不适用。

成品内容不得：

- 新增计划外事实；
- 改变角色身份、专业权限、品牌、商品或门店；
- 扩大事实确定性；
- 违反选定组件、平台、视听、禁配或缺料规则。

忠实度计算：

```text
满足的适用强制条款数 ÷ 全部适用强制条款数 × 100%
```

出现计划外事实、人物、租户、授权或品牌越界时直接失败，不允许用平均分抵消。

### 8.8 硬门八：安全、合规与权利

不得包含违法、歧视、羞辱、危险引导、无法承担的承诺、未授权第三方内容、个人隐私、企业秘密、内部提示词、系统配置、密钥、安全策略、实质性抄袭或参考语料近原文复现。

### 8.9 硬门九：生命周期与批准权

生成器输出只能进入“生成候选”状态，不得自行标记为：

- 已批准候选；
- 正式服务资产；
- 生产就绪；
- 已发布；
- 已接受知识。

状态升级必须由独立审核主体或批准流程执行。

## 9. 第一门生成器合格条件

### 9.1 父级内容候选生成器

必须同时满足：

1. 能面向20个内容产品分别生成候选，产品用户价值和形态可辨。
2. 每条输出具有来源、父级标识、生成器版本、规则版本和产品归属。
3. 能区分通用表达、合成测试和企业事实，不编造商品、库存、人物、顾客、门店、事件或效果。

5. 能产生可拆解、可复用、可组合的候选，而不只产生完整范文。
6. 能识别文本、结构和表达套路的重复或近重复。
7. 不把20产品压成统一模板。
8. 输出只进入候选区，不能自行批准。

### 9.2 内容组件候选生成器

长期内容编排资产能力视图包括：

1. 内容产品定义；
2. 场景动作内核；
3. 叙事方式；
4. 角色视角与声纹；
5. 风格向量；
6. 视听语法；
7. 连续性线索；
8. 反套路控制。

这些是同一资产模型的逻辑视图，不是八套数据库，也不是当前阶段的八类数量配额。

当前第一门只要求：

- 每个内容产品声明自己的最低必需组件；
- 20个产品的最低必需组件供给成立；
- 组件具有父级、摘要、证据区间、适用产品、兼容、禁配和缺料关系；

- 尚未被当前产品需要的长期可选组件可以后续定向补齐；
- 待修候选可以修复、合并、延期或淘汰，不得为了“清零”强行收录。

### 9.3 自动检查与回归系统

必须能够：

1. 验证对象、格式、版本、标识和必填字段；
2. 检查来源、父级、摘要和证据区间；
3. 检查非法状态升级；
4. 检查文本、结构和组件的重复或近重复；
5. 检查路线案例的预期动作和原因码；
6. 兼容已支持旧版本和新增可选字段；
7. 对未知主版本隔离并关闭失败；
8. 允许后续合法文件追加，不依赖脆弱的全仓固定文件白名单；
9. 对自身规则提供正向和反向测试；
10. 在固定输入和版本下重复运行结果一致；
11. 采用中央调度，避免检查器之间层层重复调用。

## 10. 正向父级内容与成品内容的人审评分

使用：

```text
公共质量70分 + 内容产品专属质量30分 = 100分
```

第一门用于父级正向内容；第三门启用后，同一评分结构用于成品内容候选，并附加内容编排计划忠实度硬门。

### 10.1 公共质量70分

| 评价项 | 分值 | 核心判断 |
|---|---:|---|
| 真实、证据与可追溯 | 20 | 事实、人物、事件、商品和主张是否有来源；通用或合成内容是否诚实标记 |
| 服装行业与业务具体性 | 10 | 是否进入具体服装、门店、岗位、服务、商品、陈列或经营语境 |
| 角色、品牌与视角一致性 | 10 | 谁在说、凭什么说、以什么身份说，是否自然一致 |
| 用户价值与信息增量 | 10 | 是否提供认知、决策、审美、关系或信任价值 |
| 平台原生性与执行可行性 | 10 | 时长、结构、镜头、人员和现场条件是否真实可执行 |
| 反套路、伦理与表达克制 | 10 | 是否避免假冲突、焦虑操纵、伪真实、统一机器腔和模板升华 |

### 10.2 公共项评分锚点

#### 真实、证据与可追溯：20分

| 分数 | 判断 |
|---:|---|
| 18—20 | 来源、真实模式和边界完整，未知诚实标明，无证据范围膨胀 |
| 14—17 | 主要来源可靠，少量低风险表述需要精确化 |
| 8—13 | 多处绑定不足，确定性放大，事实和表达混合 |
| 0—7 | 大量无法追溯；出现虚构或冒充真实时触发一票否决 |

#### 服装行业与业务具体性：10分

| 分数 | 判断 |
|---:|---|
| 9—10 | 有具体对象、动作、空间、岗位、业务条件和服装语境 |
| 7—8 | 大部分具体，仍有少量抽象表达 |
| 4—6 | 服装或业务只是背景，主体仍是通用观点 |
| 0—3 | 换到任何行业仍成立 |

#### 角色、品牌与视角一致性：10分

| 分数 | 判断 |
|---:|---|
| 9—10 | 身份、权限、语言、观察方式和品牌姿态高度一致 |
| 7—8 | 整体一致，存在局部口吻或权限偏移 |
| 4—6 | 角色语言趋同，存在公关腔或专业越权 |
| 0—3 | 无法辨认角色或明显冒用身份 |

#### 用户价值与信息增量：10分

| 分数 | 判断 |
|---:|---|
| 9—10 | 提供不可替代的具体价值，用户清楚为何值得看、存、搜或追 |
| 7—8 | 有明确价值，但信息增量一般 |
| 4—6 | 主要是已有信息重新包装 |
| 0—3 | 无有效信息、感官或关系价值 |

#### 平台原生性与执行可行性：10分

| 分数 | 判断 |
|---:|---|
| 9—10 | 适合目标平台，一线可在合理人员、时间和设备内执行 |
| 7—8 | 基本可执行，需要少量调整 |
| 4—6 | 平台适配较弱，执行成本或素材要求不现实 |
| 0—3 | 无法拍摄、无法口播或违背实际工作过程 |

#### 反套路、伦理与表达克制：10分

| 分数 | 判断 |
|---:|---|
| 9—10 | 真实自然，无明显套路或情绪操纵，保留合理复杂性 |
| 7—8 | 整体克制，存在轻微习惯性表达 |
| 4—6 | 有明显套话、统一结构或风格模仿 |
| 0—3 | 假冲突、假素人、身体羞辱、卖惨或强行升华严重 |

## 12. 等级、处置、状态和原因码

### 12.1 质量等级

| 等级 | 分数 | 质量含义 |
|---|---:|---|
| 甲级 | 90—100 | 可进入人工批准候选区 |
| 乙级 | 80—89 | 小改后复审；复审通过才可进入批准候选区 |
| 丙级 | 70—79 | 需要重做或重新编排 |
| 丁级 | 70以下 | 文字或对象质量本身不合格 |

质量分、硬门、否决结论和批准决定必须分开。一票否决不篡改原始质量分：即使某候选表面写作质量达到95分，只要触发否决，仍记录“原始分95、否决、拒绝”。机器硬门失败且没有进行语义评分时，质量分记录为“未评分”。

最终批准的正向分区只能包含甲级和完成修订、复审通过的乙级。原始批次中的丙级、丁级、硬门失败和否决候选必须作为失败证据保留，不能为追求“丙丁为0”而删除。

### 12.2 关键项最低线

| 关键项 | 甲级最低线 | 乙级最低线 |
|---|---:|---:|
| 真实、证据与可追溯 | 18/20 | 17/20 |
| 内容产品核心价值 | 13/15 | 12/15 |
| 角色、品牌与视角一致性 | 8/10 | 7/10 |
| 平台与执行可行性 | 8/10 | 7/10 |
| 反套路、伦理与表达克制 | 8/10 | 7/10 |

关键项不达线时，不得依靠其他分数补偿。

### 12.3 不适用项归一化

对象确实不适用某项时：

```text
归一化得分 = 实际得分 ÷ 所有适用项目满分 × 100
```

对象自身强制项、事实安全项和一票否决项不得标记为不适用。

### 12.4 四类记录不得混用

| 记录 | 示例 |
|---|---|
| 路线动作 | 阻止、请求补充、安全降级、允许 |
| 质量等级 | 甲、乙、丙、丁 |
| 生命周期状态 | 生成候选、待复审、已拒绝、已批准候选 |
| 原因码 | 事实缺失、授权缺失、输入冲突、不适用、版本不支持、重复 |

## 13. 缺陷分级与一票否决

### 13.1 缺陷分级

| 级别 | 定义 | 对批准决定的影响 |
|---|---|---|
| 致命 | 事实、安全、授权、租户、状态或权利的致命问题 | 必须拒绝；原始质量分如实保留 |
| 重大 | 产品失配、重要来源缺失、角色越权、强制规则严重偏离 | 不得批准；必须重做或重新编排 |
| 轻微 | 局部语言、镜头、平台或结构问题 | 修订并复审后批准，或记录明确豁免理由 |
| 观察 | 不影响合格性的改进建议 | 不影响批准，但保留建议 |

任何质量等级都不能覆盖致命或重大缺陷对批准决定的影响。

### 13.2 一票否决

出现任一情况，直接拒绝：

1. 把虚构商品、库存、人物、顾客、门店、事件或效果写成真实。
2. 把通用原型、表达场景或合成测试写成企业真实事实。
3. 对缺失事实进行猜测补齐。
4. 使用当前对象允许输入范围之外的事实性主张；第二、三门中包括计划外事实。
5. 把局部观察、单个体验或单一批次扩大为整体或普遍结论。
6. 跨租户调用或泄露品牌、人员、商品、门店、库存、用户或内容。
7. 泄露个人隐私、企业秘密、内部提示词、系统配置、密钥或安全信息。
8. 未取得授权却使用真人、顾客评价、声音、肖像或企业承诺。
9. 使用已撤回、过期或失效的授权、事实或角色材料。
10. 违背所选内容产品的强制输入要求。
11. 在第二、三门中违背正式内容编排计划的事实和权限约束。
12. 包含违法、歧视、危险、身体羞辱或无法承担的承诺。
13. 实质性复制冻结120条、第三方正文或现有正式资产。
14. 生成器自行将候选标为正式资产、生产可用或已发布内容。

| 逻辑视图 | 专属判断 |
|---|---|
| 内容产品定义 | 用户价值、输入合同、产品指纹、缺料行为和禁止退化是否明确 |
| 场景动作内核 | 角色、场景、对象、动作、判断点和前后状态是否可观察 |
| 叙事方式 | 信息顺序、必填槽位、真实张力、结尾和反套路边界是否明确 |
| 角色视角与声纹 | 专业权限、观察方式、语言节奏、禁区和不可模拟内容是否清楚 |
| 风格向量 | 是否拆成可独立组合维度，而不是整套固定文风 |
| 视听语法 | 镜头、声音、动作连续性和现场条件是否可执行 |
| 连续性线索 | 主体、章节、时间、未完成问题和后续方向是否可持续管理 |
| 反套路控制 | 检测对象、触发线、误报处理和修复动作是否明确 |

未在当前版本启用的逻辑视图不设数量门，也不计0分。

### 14.3 组件批准最低线

甲级组件还必须满足：

- 原子性不少于13/15；
- 可组合性不少于17/20；
- 适用、兼容和禁配边界不少于13/15；
- 当前类型专属质量不少于17/20；
- 无致命或重大缺陷。

## 15. 路线案例评价

每个内容产品至少3条，共60条，至少覆盖：

1. 必须阻止的明确无效或高风险输入；
2. 可以请求补充或安全降级的缺料输入；
3. 输入冲突、适用边界不成立或只能降级为采集任务的复杂输入。

60条路线案例的预期主动作只使用阻止、请求补充或安全降级；正常允许能力通过预先标注为可允许的正向测试输入另行验证，不混入60条路线案例。三种动作都必须被覆盖，但不机械要求平均各20条，实际分配由20个内容产品输入合同决定。

每条路线案例必须包含：

- 案例唯一标识；
- 内容产品；
- 输入摘要；
- 缺失、冲突或风险点；
- 唯一主预期动作；
- 标准原因码；
- 是否允许次级动作；
- 规则版本；
- 设计者与复核者；
- 是否属于隐藏验收集。

通过线：

- 路线准确率为60/60；路线准确表示主动作和主原因码均正确；
- 高风险案例漏放为0；
- 原型事实化、跨租户或越权放行为0；
- 合法案例错误阻止率不高于5%；分母使用预先标注应允许的正向测试输入，不使用最后挑出的240条批准材料；
- 不能通过“全部阻止”获得通过。

## 16. 内容编排计划评分（第二门生效）

| 评价项 | 分值 |
|---|---:|
| 内容产品选择 | 15 |
| 输入完整性和缺料识别 | 15 |
| 事实、主张和来源绑定 | 20 |
| 内容组件选择与兼容 | 15 |
| 角色、风格、平台和视听编排 | 10 |
| 冲突、授权和缺料处置 | 10 |
| 输出合同完整性 | 10 |
| 连续性和反重复 | 5 |

等级与处置：

| 等级 | 分数 | 处置 |
|---|---:|---|
| 甲级 | 90—100 | 可交给成品生成阶段 |
| 乙级 | 80—89 | 小修并复核后使用 |
| 丙级 | 70—79 | 重新编排 |
| 丁级 | 70以下 | 拒绝并回到输入或规则修复 |

## 17. 多样性、盲测和变形测试

### 17.1 近重复率

```text
近重复条目率
= 涉及至少一个经人工确认近重复关系的唯一正向条目数
÷ 当前受评正向条目总数
```

运行清单必须记录比较算法、阈值、比较范围和算法版本。机器相似命中只负责进入复核队列，最终近重复结论由人审确认。明显套话或近重复条目率不得超过10%，最终正向清单的归一化完全重复数量和来源近原文复现数量均必须为0。

### 17.2 结构集中度监测

除内容产品明确定义的固定语法外，以下作为复核触发线，而不是机器自动淘汰线：

- 同一产品中单一叙事方式超过40%；
- 完全相同风格组合超过30%；
- 固定开头结构超过20%；
- 单一结尾、口头禅、镜头链或角色语气显著集中；
- 生成结果对冻结120条或既有正式资产产生高重合。

每个产品达到12条时，完全相同的开头骨架、结尾骨架或完整修辞指纹任一超过2条也触发复核。触发后由人审判断是产品必要语法还是公式化；结论和版本化例外理由必须记录，最终未解决的公式化发现必须为0。

### 17.3 内容产品盲测

隐藏产品编号和标题后，由审核者判断属于哪个内容产品。

第一门初始通过线：

- 总体第一选择识别率不低于85%；
- 每个产品至少9/12被正确识别；
- 任意两个产品双向混淆率超过25%时必须复核产品指纹；
- 不能依靠标题直接写出产品名称；
- 持续高混淆的产品必须回到产品定义或生成器修复，不能靠改标签解决。

总体90%、每产品85%作为运行数据成熟后的收紧目标，不在尚无真实基线数据时提前作为首批硬门。主审可在显示产品标签前先记录盲判，再显示标签完成正式评分，避免重复建立一套全量人审。

### 17.4 分阶段变形测试

| 测试 | 第一门 | 第二门 | 第三门 |
|---|---:|---:|---:|
| 更换内容产品，观察产品价值和结构变化 | 必须 | 必须 | 必须 |
| 删除必填输入，观察动作变化 | 必须 | 必须 | 必须 |
| 固定事实，更换风格 | 可选 | 必须 | 必须 |
| 更换企业或品牌，检查残留 | 不适用或合成测试 | 必须 | 必须 |
| 相同输入重复生成，检查事实稳定和表达多样 | 必须 | 必须 | 必须 |
| 撤回授权或标记过期 | 合成路线案例 | 必须 | 必须 |

每个生效的关键行为至少有一个正向和一个反向确定性测试。测试数量随风险扩展，不为凑固定总数重复制造同类案例。

## 18. 批次整体通过线

### 18.1 第一门：生成器与300条

- 20个内容产品全部有正向和路线案例；
- 240条正向和60条路线案例分别编目；
- 300/300具有来源、版本、产品归属和审核记录；
- 机器检查覆盖300/300；
- 密封正向批次首次可接受率总体不少于90%；
- 每个产品达到12条验证样本时至少11/12首次可接受；
- 最终批准正向分区达到240条，且只含甲级和修订复审通过的乙级；
- 所有密封批次中的一票否决为0；
- 明显套话或近重复不超过10%；
- 60条路线案例全部作出正确主动作；
- 高风险漏放、跨租户、虚构事实和自行批准均为0；
- 检查器正反测试、旧版本兼容和新增合法文件检查通过；
- 运行清单、不可变摘要和人审记录齐全。

### 18.2 第二门：内容编排计划

- 甲级加乙级不少于95%；
- 事实绑定遗漏为0；
- 计划外事实、错误人物、错误品牌和错误租户为0；
- 缺料、冲突、撤回和过期动作符合合同；
- 乙级完成修订复审后才能交给成品生成。

### 18.3 第三门：成品内容候选

- 适用强制条款忠实度不低于95%；
- 计划外事实、权限偏离和跨租户为0；
- 内容产品盲测达到本标准目标线；
- 明显套话或近重复不超过10%；
- 一线真实执行抽测合格率不低于85%；
- 安全、隐私和授权致命问题为0；
- 所有输出仍处于候选或人审状态，不自动发布。

### 18.4 第四门：自动检查与完整回归

- 全量机器检查按清单通过；
- 已支持旧版本、可选字段、未知主版本和合法新增文件行为正确；
- 高风险漏放为0；
- 合法案例错误阻止率不高于5%；
- 固定输入和版本重复运行结果一致；
- 快速检查和完整回归没有重复嵌套同一重检查；
- 隐藏验收集与开发调参集分离；
- 检查失败不得通过降低格式、权限、隔离或安全严格度解决。

## 19. 人审组织与职责

### 19.1 审核角色

| 角色 | 主要职责 |
|---|---|
| 内容运营专家 | 内容产品、用户价值、叙事、平台、风格和反套路 |
| 服装领域专家 | 工艺、面料、版型、商品、陈列和专业主张 |
| 零售运营专家 | 门店、服务、人员、空间和一线执行 |
| 品牌或经营负责人 | 品牌姿态、经营判断、企业承诺和公开边界 |
| 合规审核人 | 权利、隐私、广告主张、承诺和高风险内容 |
| 技术审核人 | 格式、版本、血缘、摘要、路由、状态和检查器 |
| 守护审查方 | 审查实现、证据、机器门、假绿风险和高风险样本，不替代内容主审 |
| 项目发起人 | 批准总体门禁结论、例外和代表性样本，不要求逐条主审全部材料 |

不是每条材料都要由全部角色重复审核。主审角色按内容产品和风险分配；涉及专业事实、真人、承诺、隐私或高风险主张时增加对应专家。

### 19.2 覆盖与复审

- 机器检查：全部材料和案例100%；
- 内容主审：密封资格和稳定性批次的全部正向首次输出100%，包括最终未被批准的失败候选；
- 路线案例标准答案：60条全部由设计者以外的审核者确认；
- 第二专家：正向材料不少于48条，并保证每个产品至少2条；其余样本覆盖不同等级、角色、平台和风险；
- 路线案例第二复核不少于12条，所有高风险和意见不一致案例全部复核；
- 一票否决意见不一致、相差超过10分、跨越一个以上等级或涉及高风险的，全部裁决；
- 守护审查方检查全量结构证据和硬门结果，并抽查语义高风险样本，不重复进行180条或300条全量内容主审。

### 19.3 审核一致性

正式审核前使用校准样本统一锚点。审核者尽量不知道生成器版本，减少先入偏见。

硬否决意见一致率必须为100%，批准或不批准的决定一致率目标不低于90%。双审样本不少于40且至少出现两个等级时，可以监测加权一致性系数：首版目标不低于0.60，成熟目标不低于0.70。等级分布过于单一时记录“不可解释”，不得伪造为0或1。该指标用于发现标准或培训问题，不作为首批300条唯一硬门。

## 20. 状态迁移

```text
生成候选
→ 机器硬门通过
→ 人工主审完成
→ 第二复审或裁决（适用时）
```

质量等级本身不直接改变状态，由独立的批准决定驱动状态迁移：

| 批准决定 | 状态 |
|---|---|
| 批准 | 已批准候选 |
| 轻微修订 | 轻微修订待复审 |
| 重做或重新编排 | 重做或重新编排 |
| 拒绝 | 已拒绝 |
| 隔离 | 已隔离待版本或安全处理 |

甲级通常可以批准，但仍须通过全部适用硬门且无未解决缺陷；乙级完成轻微修订和复审后才可批准；任何等级触发否决时均必须拒绝。

“已批准候选”仍不等于正式服务资产、生产可用、已发布或客户可见。进入正式内容资产数据库、运行服务或发布区必须经过后续独立流程。

每次修改和复审必须新增记录，不能覆盖原结论。

## 23. 第一门最终准入判定

生成器和300条基线只有同时满足以下条件，才可作为后续系统建设的输入：

1. 冻结120条完成只读映射并得到真实合格数 `N`。
2. 20个内容产品均达到最低正向和路线案例覆盖。
3. 正向分区总计240条，路线分区总计60条，二者没有混装。
4. 20产品最低必需组件供给、来源、父级、证据区间、兼容、禁配和缺料关系成立。
5. 正向批次和单产品通过率达到第18章要求。
6. 60条路线案例全部作出正确主动作，高风险漏放为0。
7. 虚构事实、未授权冒用、跨租户、泄密和自行批准为0。
8. 内容产品盲测达到第一门初始通过线，多样性硬门通过，所有公式化复核发现均已关闭或具有版本化产品例外。
9. 自动检查覆盖全部案例，正向、反向和兼容回归成立。
10. 内容主审、第二专家复审、分歧裁决和失败记录完整。
11. 生成器、规则、案例集、输出、检查器和审核批次具有不可变清单与摘要。
12. 项目发起人批准总体门禁结论和代表性样本。

第一门通过只代表：

- 生成器具备进入正式内容资产数据库建设的资格；
- 300条可以作为后续内容资产拆解、内容编排计划和运行系统建设的共同评价基线。

第一门通过不代表：

- 正式内容资产数据库已经完成；
- 内容编排计划已经完成；
- Dify工作流已经完成；
- 企业真实输入和品牌数据库已经完成；
- 云端部署、一键部署、内部试运行或生产就绪已经完成。

## 24. 最终原则

评价体系不能只筛选“文字写得好不好”，也不能因为偏爱统一的钩子、冲突、反转和升华，重新制造另一套公式化生产线。

正确的标准应同时保护：

- 真实和证据边界；
- 20个内容产品的真实差异；
- 服装行业与门店一线的具体性；
- 角色、品牌和用户的尊严；
- 组件复用与长期积累；
- 对缺料、冲突、撤回和不适用的诚实处理；
- 生成、审核、批准和发布之间的权力分离；
- 简单、可执行、可验证而不过度工程化的实现路径。
